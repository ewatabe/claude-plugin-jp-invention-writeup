# 明細書の章立てと文体ルール（JPO実務準拠）

JPO（特許庁）実務の明細書スタイル。組織内の過去サンプル `~/patent/sample/明細書.docx` があれば優先的にそれに寄せる。

## 章立て（順序固定）

```
【書類名】明細書
【発明の名称】
【技術分野】
　【００XX】本文
【背景技術】
　【００XX】本文
【先行技術文献】
　【特許文献】
　　【００XX】
　　【特許文献１】公報番号
【発明の概要】
　【発明が解決しようとする課題】
　　【００XX】本文
　【課題を解決するための手段】
　　【００XX】本文
　【発明の効果】
　　【００XX】本文
【図面の簡単な説明】
　【００XX】
　【図１】本文
　【図２】本文
　...
【発明を実施するための形態】
　【００XX】本文
　...
【符号の説明】
　【００XX】
　　１　〇〇
　　２　〇〇
　...

【書類名】特許請求の範囲
【請求項１】
　...
【請求項２】
　...

【書類名】要約書
【要約】
【課題】
【解決手段】
【選択図】図N
```

## 段落番号ルール

- **【００XX】** は **全ての段落に付与**（章節見出し直後を含む）
- 番号は **明細書全体で連番**、4桁ゼロ詰めの全角数字
- 章節見出し（【背景技術】等）には番号を付けない。直後の本文段落に付ける

## 文体ルール

| 項目 | ルール | 例 |
|---|---|---|
| 文末 | 「〜である」「〜する」「〜である。」 | 「〜を備えることを特徴とする。」 |
| 主語省略 | システム発明は主語を「本実施形態に係る〇〇システムは、」と明示 | |
| 受動態 | 多用する | 「〜が表示される」「〜が生成される」 |
| 体言止め | しない | × 「〇〇の表示」→ ○「〇〇を表示すること」 |
| 数値表記 | 参照符号・段落番号は全角数字 | 「サーバ１００」「【００１１】」 |
| 図番参照 | 「図１に示すように、」で開始することが多い | |
| 「等」の使用 | 列挙の最後に「〜等」を付けて開示範囲を広げる | 「単一塩基変異、多塩基変異、挿入欠失変異、構造変異等」 |

## 章別の書き方の型

### 【技術分野】（1段落）

```
【００XX】
本開示は、〇〇〇〇、〇〇〇〇方法及びプログラムの技術に関する。
```

### 【背景技術】（2〜4段落）

- 1段落目：技術領域の一般的な状況・課題
- 2段落目：既存技術での解決アプローチ
- 3段落目（オプション）：特許文献の引用と要約

### 【先行技術文献】

```
【特許文献】
【００XX】
【特許文献１】特表２０２１－５３００５２号公報
【特許文献２】特開２０２０－〇〇〇〇〇〇号公報
```

### 【発明が解決しようとする課題】（1〜2段落）

- 1段落目：「しかしながら、〜は依然として時間を要する」「〜は困難である」など、既存技術の限界
- 末尾段落：「このような背景に鑑みて本開示がなされたのであり、本開示は、〜を目的とする。」

### 【課題を解決するための手段】（1〜2段落）

- 独立項の要約を平易に述べる
- 「前記した課題を解決するため、本開示は、〜を含む情報処理システムである。」
- 末尾に「その他の解決手段は実施形態中において適宜記載する。」

### 【発明の効果】（1段落）

```
【００XX】
本開示によれば、〜することができる。
```

### 【図面の簡単な説明】

```
【００XX】
【図１】本実施形態に係る〇〇システムの構成例を示す図である。
【図２】〇〇の詳細な構成を示す図である。
【図３】〇〇のハードウェア構成を示す図である。
```

末尾は **「〜を示す図である。」** または **「〜を示すフローチャートである。」**

### 【発明を実施するための形態】

- 各図ごとに段落を分けて説明
- 「図１に示すように、〜は〜を備える。」で始めることが多い
- 参照符号は本文中で全角数字
- システム→構成要素→処理フロー→画面例 の順で展開

### 【符号の説明】

```
【００XX】
　　１　参加者端末
　　２　主治医端末
１００　〇〇サーバ
　１１０　処理部
　１１１　モジュールA
```

- 番号順にソート
- 番号は右揃え（3桁分のスペース）
- 階層的構造はインデント

### 【要約書】

```
【書類名】要約書
【要約】
【課題】〜することを目的とする。
【解決手段】〜
【選択図】図N
```

- 課題は1文
- 解決手段は3〜5文
- 選択図はシステム全体構成を示す図（通常は図1または図2）
