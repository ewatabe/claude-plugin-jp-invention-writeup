# 図面と参照符号のルール

過去の特許出願サンプル（`~/patent/sample/` 配下に過去案件の図面PPTXがあれば参照）から抽出した実務慣例。サンプル未配置でも、以下のルールに沿って図面を作れる。

## スライドのヘッダ（必須）

各図面スライドの上部に以下を配置：

```
【書類名】　図面     （左上）
【図N】              （次の行）
図 N                 （図のキャプション中央上、大きめのフォント）
```

## 参照符号の付与ルール

### 番号体系

- **主要な構成要素**：10, 20, 30, 100, 200…（二桁または三桁の刻み）
- **下位部品**：主要要素番号＋連番（例：100の下位なら 110, 111, 112、または 101, 102）
- **データ・情報の例**：単独で 1, 2, 3… を割り当てる場合もある（サンプルでは端末＝1, 2、サーバ＝100）

過去サンプル明細書（あれば）の【符号の説明】に倣う：

```
　　１　参加者端末
　　２　主治医端末
　　３　外部DB
　　４　外部知識DB
　　５　〇〇
　　６　〇〇
１００　会議運用支援サーバ
　１１０　処理部
　　１１１　〇〇モジュール
　　１１２　〇〇モジュール
```

### 配置ルール

- 参照符号は **対象図形の近傍**（左上、右上、外側いずれか）に **小さめのテキストボックス** で配置
- ラベル（「参加者端末」など）は図形の **内部** に
- 参照符号と図形の対応が一目で分かるように、必要なら引出線（freeform line）を引く
- 同じ参照符号は **明細書全体で同一物を指す**：図1で「100」と振ったら、図2でも「100」は同じ「会議運用支援サーバ」

## 図形の種類と用途

| 図種別 | 用途 | 主に使う図形 |
|---|---|---|
| システム構成図 | 主要要素間の関係 | Rectangle, Arrow |
| ブロック図 | モジュール内訳 | Rectangle (nested) |
| ハードウェア構成図 | HW要素 | Rectangle, Line |
| ER図 | データ構造 | Rectangle, Line |
| データの例 | テーブル例 | Table |
| フローチャート | 処理フロー | Rectangle, Rhombus, Arrow |
| 画面例 | UIモック | Rectangle, Text |

## 色・フォント

- **モノクロが原則**（特許図面はモノクロ印刷想定）
- ただし社内提出時はカラーで作って問題ない。事務所側でモノクロ化する場合もある
- フォント：Yu Gothic / Meiryo（CJK対応必須）
- 文字サイズ：ラベル 10-12pt、参照符号 10-11pt、図番号 16-20pt

## キャプション

スライドの下部または上部に必ず：

```
図N
```

をやや大きめのフォントで配置。サンプルでは「図 1」（半角スペース挟み）の形式が使われている。

## 図面リストとの整合

`work/figure-list.md` の図番・タイトルと、各スライドの 【図N】 が完全一致すること。
途中で図番を入れ替える場合は、figure-list の更新 → 全スライド更新 → 説明文の更新 → 請求項参照（必要なら）の順で揃える。

## スライドサイズ

- 16:9 （13.333 inch × 7.5 inch）が既定
- ただし特許庁提出時は A4縦の図面台紙に貼り直す場合がある。事務所側で処理することが多い

## matplotlib でグラフ図を生成する場合の注意

Phase 4 の図9（VAF分布等）のような matplotlib 生成図では、Linux環境のデフォルトフォントに **日本語が含まれない場合** がある（DejaVu Sans のみ等）。豆腐化を回避する3つの選択肢：

1. **英語ラベルにする（推奨・即効）**: 軸ラベル・タイトル・凡例を英語にする（例：Frequency, Score, Category 等の汎用語、あるいは案件固有の英語専門用語）。明細書本文の日本語説明で補う。技術用語は英語が国際標準なので違和感少
2. **`fonts-noto-cjk` をインストール**: `sudo apt install fonts-noto-cjk` 後、`matplotlib.rcParams["font.family"] = ["Noto Sans CJK JP", ...]`
3. **HTML+SVG で書き直す**: 散布図・分布図は HTML+SVG の方が見栄えが良い場合が多い。実施例UIモック扱いにして `references/ui-mockup-html.md` のフローで生成

特に「請求項添付の特許図面」と「明細書中の説明用グラフ」は性質が違う。請求項添付は線画ベースが基本、明細書中の説明用は写実性より分かりやすさ優先。

## 画面例（UIモック）図面の作り方

請求項の対象がアプリケーション画面である場合、「画面例」図面は **実際のアプリ画面に近いUIモック** にすると進歩性主張の説得力が増す。単純な矩形ブロック図では不十分。

### 推奨パターン: `figure_type: "html_file"` モード

```json
{
  "figure_number": 11,
  "title": "差分提示画面の例を示す図",
  "figure_type": "html_file",
  "html_path": "../figure-html-custom/figure-11.html"
}
```

- カスタムHTMLは `work/figure-html-custom/figure-NN.html` に保存（保護領域）
- `build_figure_html.py` が work/figure-html/ にコピー
- Puppeteer で PNG に
- `build_figure_pptx.py --rendered-dir` で図面.pptx に埋込

### UIモック HTML の構造

`templates/ui-mockup.template.html` の構造を踏襲しつつ、特許図面ヘッダを追加：

```html
<div class="slide">
  <!-- 図面ヘッダ -->
  <div class="fig-header-doctype">【書類名】　図面</div>
  <div class="fig-header-figno">【図N】</div>
  <div class="fig-header-figbig">図 N</div>
  <div class="fig-title-caption">{{タイトル}}</div>

  <!-- 画面フレーム（境界 2.5px） -->
  <div class="screen">
    <div class="ref" style="left:10px;top:8px;">G1</div>
    <!-- アプリヘッダ・タブ・メインパネル... -->
    <!-- 各パネルの ref は box の左外 (-34px) に配置 -->
  </div>
</div>
```

- **参照符号**は HTML の `.ref` クラスで画面要素の左上に配置（`G1`〜`Gn` または `H1`〜`Hn` 等）
- 発明説明資料の実施例スライド（exhibit-*.html）と同じUI言語を使うとブランドが揃う
- 図面の場合は外周に **画面フレーム枠** を入れる（境界が明確になる）

### Phase 2 の実施例HTMLを図面に流用するときの簡易化

`work/figure-html-custom/exhibit-*.html` をコピーして図面用HTMLにする際は以下を適用すると、整合性とJPO実務適合性が両立する：

| 変更前（実施例） | 変更後（図面） | 理由 |
|---|---|---|
| 主色: ヘッダ等のブランドカラー | グレー〜白基調 | モノクロ印刷想定 |
| `box-shadow` / `backdrop-filter` | 削除 | 線画ベースを徹底 |
| アクセント色のバッジ・ピル | 黒〜濃グレーの輪郭線 | 同上 |
| 吹き出しによる説明 | 削除（明細書本文に移譲） | 図面に説明テキストを直書きしない |
| 画面外周なし／薄枠 | `border: 2.5px solid #000` の画面フレーム | 図面としての境界明示 |
| 装飾アイコン（絵文字含む） | 抽象記号 or 削除 | 環境依存を排除 |
| 参照符号なし | `.ref` で `G1`〜`Gn` を要素左外側に配置 | 参照符号必須 |

詳細フローは `phases/4-figures-and-spec.md` の「実施例HTMLを図面に流用するワークフロー」を参照。

## やってはいけないこと

- 参照符号の重複（番号体系内で同じ番号を別物に使う）
- 図面間での参照符号の不整合（図1で「100」がサーバ、図2で「100」がDB、はNG）
- 写真・ビットマップ画像の使用（実施例の画面キャプチャを除き、原則ベクタ図形）
- 過度な装飾（影、グラデーション、3D効果）
